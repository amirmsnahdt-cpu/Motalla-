# بده بستون (اپ واریزی مطلا)

Single-page PWA for the gold shop مطلا: deposits, split into bank sources, tracking, customer accounts.
UI is Persian/RTL. Owner writes Persian; reply in Persian.

## Files
- `index.html` — shell only (~5KB): meta, boot/update-swap script, `const APP_V`, loads `app.js` + `styles.css`.
- `src/js/*.js` — THE JS SOURCE, edit here. One classic script, globals; joined in filename order.
- `src/css/*.css` — THE CSS SOURCE, edit here. Order matters: later rules override earlier; new overrides go at the END of the last file.
- `app.js`, `styles.css` — GENERATED by `tools/build.py` (concatenation, header carries a hash). Never edit or read them.
- `server/server.js` — Node server on Liara. Serves only paths listed in `STATIC`; add new static files there.
- `sw.js` — network-first service worker.
- `android/` — WebView shell (loads the Liara URL). Icons in `android/app/src/main/res/mipmap-*`.

## Lists (v52)
- A list = one PAY date (`ldKey`, `PD(r)`), whatever the registration dates. Lists page = `split1` (cards, newest first);
  one list = `lday` (`vLday`/`hubData`): errors, unallocated, each source (ready to send / sent with ✓ ✕ and receipts), customer-settled.
- `parts()` = allocations of the current list from every `drafts` bucket (old buckets are keyed by registration date; membership comes
  from the rows' pay date, nothing is migrated). Add/remove with `addPart`/`delPart`. New batches use `date=pay=ldKey`; items carry `pay`.
- Archiving a list (`hubClose`) closes only its own rows; a shared legacy batch is split and moved items keep their photo keys (`imgs`).
`python3 tools/css_dedupe.py` reports declarations that a later identical selector always overrides (dead code);
`--write` removes them. Run it after CSS work; verify with `tests/smoke.mjs --styles` before/after (computed styles must match).

## app.js concepts
- render(): view table `R={view:[vX,aX]}`; navigate with `go('view')`. Actions: `ACT.name` + `data-act="name"`.
- Data: `validated()`, `PD(x)` (pay date), `drafts[date]`, `batches`, `stOf(id)`. Split: `parts()`, `allocMap()`, `splitAuto()`.

## Workflow
1. Edit `src/` with targeted greps; don't read whole files.
2. `python3 tools/bump.py <new version>` (rebuilds app.js/styles.css, updates APP_V, boot V, `?v=`).
   Deploy fails if app.js/styles.css are stale (`python3 tools/build.py --check`).
3. Tests: `npm test` (server API, no deps) and `node tests/smoke.mjs` (Playwright: real server with temp data,
   opens all 26 views, fails on any JS error). Both run in CI (`.github/workflows/tests.yml`); deploy runs `npm test`.
4. Commit, push to main, send the user:
   `https://raw.githack.com/amirmsnahdt-cpu/Motalla-/<SHA>/index.html`
5. Production deploy runs nightly 00:05 Tehran (`.github/workflows/deploy-liara.yml`).
   Manual: `gh workflow run deploy-liara.yml --ref main -R amirmsnahdt-cpu/Motalla-`.

## Rules from the owner
- Root-cause fixes, no leftover bugs. Simple iOS-like blue UI, rounded cards, bold amounts.
- Status frames: green settled, yellow pending, red unconfirmed — one clean rounded border, no halo.
- Repo is public: never commit customer data, phone numbers or national IDs. Liara token lives only in GitHub secrets.

## Server data safety
- Staff may only ADD audit rows; on existing rows only `undone:true` is accepted (`auditEditOk`). Audit is never deleted.
- Replacing/deleting an existing image needs edit/track/debt/del (`IMG_PERMS`); the previous copy goes to `imgs_old` (kept 90 days).
- `/api/backups` returns `lastDl` (last backup download from any device) for the off-server backup reminder.
- Android signing: ONLY from secrets `ANDROID_KEYSTORE_B64`, `ANDROID_KEY_PASS`, `ANDROID_KEY_ALIAS` (build fails without them).
  No key or password may ever be committed (`*.keystore`, `*.jks` are gitignored). Key generation 2 (v57.1): the APK reports
  `AndroidBridge.keyGen()==2` and the workflow writes `dist/apk-key.txt`; `/api/status.apkKey` tells old apps (old leaked key)
  to show the one-time reinstall guide (`15g-android-key.js`). Never change the key again without the same migration.

## In-app update (careful)
- Production: client polls `/api/status` (version read from `const APP_V` in index.html) and reloads.
- githack: client fetches `<sha>/index.html`, rewrites `app.js`/`styles.css` to that sha's absolute URL,
  stores it in localStorage, and the boot script swaps it in. Any new file loaded by index.html must be
  added to that rewrite regex in `checkUpdate` and to `STATIC` in server.js.

## Customer accounts & documents (v53 → v56)
- Everything lives in `custs` (synced). Real customers = `CU()` (no `sys`). System records: `{sys:'ch',kind:'pos'}` POS terminals (old `kind:'bank'` records still work), `{sys:'cfg',groups,goods}`. Never list `custs` directly as customers — use `CU()`.
- Balance per tx = `txD(t)` → `{r,g,x}` (positive = we owe = customer «طلبکار از ما»; negative = «بدهکار به ما»). `cuBal(c)` → `{R,G,X}`; X = coins/currency per key of `XA` (امامی، بهار، نیم، ربع، گرمی، USD، EUR، AED).
- One document type `inv` (UI calls it «سند»): `items` (goods with اجرت `ajP` % and `ajT` toman together; old rows `ajU/aj` read by `ajPT`), `xr` (gold/coin/currency rows: `t` sell|buy|in|out, `pul` = پولی: nothing delivered, amount and goods both go to the account), `pays` (`m` cash|pos|hav|cust; out = negative amount; havale to our bank `srcId` = a `sources` account, legacy `chId`), `total` (net rial of goods, may be negative), `ge` gold effect (g ۱۸), `xe` coin/currency effect, `gc` rest booked as gold.
- Gold math: header has مظنه and «هر گرم ۱۸» linked (`MZK`=4.3318). Buy متفرقه = rate×735/750, sell متفرقه = rate×740/750 (`xrAy`); پولی rows default 750. Gold xr effect = weight×ayar/750.
- Bank tab: POS balance (`chBal`) = cards taken in documents − deposits to a bank account (`posDep`: ch `tout` with `srcId` + source `led` row `pos` with `chTx`; deleting the ledger row also deletes the tout). Source balance `acEst` includes document havale (`srcMoves`).
- Customer page quick actions open a new document with a prefilled row (`svNew({cu,pre:'in'|'out'|'gin'|'gout'})`). Customer form suggests name/phone/national ID from entries and accounts (`acList`, `bzPeople`), groups from `groupsList()`.
- Day list export (`ldExp`): per-deposit checkboxes (`ldX`), default = all rows allocated to a source; `ldPick()` returns the selection.
- Motion (09-v56 CSS): sheets slide up with an iOS spring and the page behind scales (`html.shopen`); `closeSheet` animates a cloned ghost so the real sheet closes synchronously; drag a sheet down to close.
