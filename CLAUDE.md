# بده بستون (اپ واریزی مطلا)

> Owner rules, design rules, accounting rules and workflow for ANY AI: read `AGENTS.md` first. This file is the technical map.

Single-page PWA for the gold shop مطلا: deposits, split into bank sources, tracking, customer accounts.
UI is Persian/RTL. Owner writes Persian; reply in Persian.

## Files
- `index.html` — shell only (~5KB): meta, boot/update-swap script, `const APP_V`, loads `app.js` + `styles.css`.
- `src/js/*.js` — THE JS SOURCE, edit here. One classic script, globals; joined in filename order.
- `src/css/*.css` — THE CSS SOURCE, edit here. Order matters: later rules override earlier; new overrides go at the END of the last file.
- `app.js`, `styles.css` — GENERATED by `tools/build.py` (concatenation with block comments stripped — v78.8; the token stream is identical, src/ keeps the comments; header carries a hash). Never edit or read them.
- `server/server.js` — Node server on Liara. Serves only paths listed in `STATIC`; add new static files there.
- `sw.js` — network-first service worker.
- `android/` — WebView shell (loads the Liara URL). Icons in `android/app/src/main/res/mipmap-*`.

## Print / PDF pipeline (learned the hard way in v90.6)
One HTML string (`invDoc`, `pdfDoc`-based reports) is rendered by THREE different engines; a sheet must be checked in each:
- **Preview** (`openPrint`, 04): `<iframe srcdoc>` in SCREEN media. A style is injected: `body{width:<paper px>!important;padding:<@page margins>!important;background:#fff!important;…}`; margins come from `pageSpec(html)` (15o), whose regex needs `margin:<n>mm` — `margin:0` (no unit) silently becomes 8mm.
- **Phone PDF** (`pdfMake`, 15o — iPhone AND the Android app; this is what «چاپ / ذخیره PDF» and «اشتراک» send): the html is laid out in a hidden iframe (screen media, width = paper − margins), `@page` is dropped, `@media print{` becomes `@media all{`, `html`/`body` selectors become `.__pb`, every `url()` becomes a data: URI, then each page is drawn through SVG `<foreignObject>` to a JPEG. Consequences: `<body>` must have NO class (the code adds `class="__pb"` → duplicate attribute → the SVG fails and the PDF is never made); rules meant only for the on-screen preview must be scoped `html body …` (no `html` inside the SVG, so they die there); only fonts declared in the sheet's own `<style>` exist; keep CSS conservative (flex, fixed mm sizes, borders, inline SVG; avoid `position:absolute`, filters, blend modes).
- **Desktop browser** (`printReport`, 08): flowing reports are copied into `#printArea` of the app document (the app's own CSS applies to short class names there!); documents made of `section.sht` are printed from a hidden iframe (`printFrame`) instead.
- **Flowing reports** (`pdfDoc` + `pdfCSS`, 08: deposit list, statement, bank statement): white paper with `@page` margins; `pdfMake` finds the page cuts itself (under `tr`, `h2`, `.kp`, `.sub`, `.top` …, repeats `thead`). Keep that stylesheet ONE layer — stacking a new look on top of the old rules is what broke these PDFs in v89.7–v90.7.
- **Ready-made sheets**: a document that paginates itself uses `<section class="sht">` elements exactly the paper size with `@page{size:…;margin:0mm}`; `pdfMake` then makes one full-bleed page per section (no cutting, no white margin) and the preview shows them as separate sheets.
- Test with the real functions in Playwright — `await pdfMake(html,'t',true)` → `fl._pages[i].j` (JPEG), `openPrint(()=>html)` + screenshot — not with `page.pdf()`. Arabic shaping joins letters across inline tags: always put a real space between a label and the small text after it.
