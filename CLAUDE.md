# بده بستون (اپ واریزی مطلا)

> Owner rules, design rules, accounting rules and workflow for ANY AI: read `AGENTS.md` first. This file is the technical map.

Single-page PWA for the gold shop مطلا: deposits, split into bank sources, tracking, customer accounts.
UI is Persian/RTL. Owner writes Persian; reply in Persian.

## Files
- `index.html` — shell only (~5KB): meta, boot/update-swap script, `const APP_V`, loads `app.js` + `styles.css`.
- `src/js/*.js` — THE JS SOURCE, edit here. One classic script, globals; joined in filename order.
- `src/css/*.css` — THE CSS SOURCE, edit here. Order matters: later rules override earlier; new overrides go at the END of the last file.
- `app.js`, `styles.css` — GENERATED by `tools/build.py` (concatenation with block comments stripped — v78.8; the token stream is identical, src/ keeps the comments; header carries a hash). Never edit or read them.
- `server/server.js` — Node server on Liara. Serves only paths listed in `STATIC`; add new static files there.
- `sw.js` — network-first service worker.
- `android/` — WebView shell (loads the Liara URL). Icons in `android/app/src/main/res/mipmap-*`.

## Server data safety
- Staff may only ADD audit rows; on existing rows only `undone:true` is accepted (`auditEditOk`). Audit is never deleted.
- Replacing/deleting an existing image needs edit/track/debt/del (`IMG_PERMS`); the previous copy goes to `imgs_old` (kept 90 days).
- v78.9 delete-by-overwrite: without `del`, the server rejects replacing a customer with a copy that drops tx rows (soft `del:true` is fine), empties its name or changes `sys`, and replacing a deposit with an empty name/amount (`txGone`, `guardDoc`). Deleting a customer or removing its tx rows keeps the previous copy in `docs_old` (90 days). Deleting `trash` docs needs `del`.
- v78.9 githack preview: raw.githack.com is ONE origin shared by every GitHub repo, so in the preview (`PVW`) all storage goes through `LS` = sessionStorage (01-core; old preview localStorage is moved there once, then removed), images stay out of IndexedDB, the boot swap reads only sessionStorage. Never use `localStorage` directly in src/js — use `LS`. Server: a login from the preview, or any token used from it, lasts at most 1 hour (`sessions.pv`, `previewExp`).
- v79.2 user deletion: server data never depends on the user row (docs keep only names; deleting a user cascades only sessions/bio keys — test «حذف کاربر»).
